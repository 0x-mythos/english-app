# Банк текстів для читання — формат

Один файл на текст: `data/reading/<id>.json`, `id` = ім'я файлу (`rb-b1-01`, `rb-b2-03`). Генерується субагентами/вручну в Claude Code (не через API), перевіряється тестом схеми всіх файлів. Банк віддається з fs на сервері; клієнт отримує текст без `answer` і `explanation`.

```json
{
  "id": "rb-b1-01",
  "level": "B1",
  "topic": "code_review",
  "title": "My first code review",
  "text": "Перший абзац.\n\nДругий абзац.",
  "glossary": [
    { "lemma": "approve", "forms": ["approved"], "translation": "схвалювати", "transcription": "/əˈpruːv/" }
  ],
  "questions": [
    { "prompt": "What did the author feel at first?", "options": ["A", "B", "C", "D"], "answer": 1, "explanation": "Пояснення українською." }
  ]
}
```

## Поля
- `id` — унікальний, збігається з ім'ям файлу.
- `level` — `B1` або `B2`.
- `topic` — один із: `code_review`, `api`, `devops`, `meetings`, `interview`, `data`, `general_it`, `everyday`. Частка текстів із `topic` ≠ `everyday` — не менше 60%.
- `title` — коротка англійська назва.
- `text` — 120–220 слів, абзаци розділені `\n\n`. Звичайний апостроф `'` і прямі лапки `"`; без розмітки.

## Рівні
- B1: прості конструкції, поширена лексика, короткі речення.
- B2: складніші речення (підрядні, пасив, умовні), ширша лексика, але без рідкісного академізму.
- Читач — junior backend-розробник. Текст має читатися як реальна історія чи пост, не як підручник. Без реальних компаній і фактів про реальних людей.

## Глосарій
- 10–20 записів; `lemma` — одне слово (не фраза), не порожня.
- `forms` — усі форми цієї леми, що реально є в тексті як цілі слова (без урахування регістру), хоча б одна. Дублікатів форм між записами немає.
- `translation` — українською; `transcription` — IPA в слешах.
- Обираємо слова, яких B1 може не знати; дуже базову лексику не беремо.

## Питання
- 2–3 на розуміння змісту (не дрібні деталі), 3–4 різні варіанти, `answer` — індекс правильного, рівно одна однозначно правильна відповідь.
- `explanation` — українською, 1–2 речення.
